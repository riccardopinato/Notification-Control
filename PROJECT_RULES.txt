NOTIFICATION CONTROL — PERMANENT PROJECT RULES

PRODUCT
- Notification Control is one app, not a bundle of disconnected micro-apps.
- Luminous Infinite Circle is the visual-alert donor/module.
- Core modules: Vault/Undo, Rules, Critical Alert, Follow Up, Pausa Ping, Pickup Code, Luminous.
- Free must be genuinely useful; Premium unlocks automation/control, not relief from artificial frustration.

DATA & PRIVACY
- Local-only by default; no cloud required for core use.
- Notification content is canonical local data and must never be uploaded silently.
- Android automatic cloud backup remains disabled until an explicit encrypted backup design exists.
- Google Sign-In is optional and must not gate local value.
- Security features must distinguish account identity from local Vault protection.

CAPTURE ARCHITECTURE
- Single Capture: one NotificationListenerService.
- Single Vault: one canonical local persistence layer.
- Multiple Consumers: Rules/Luminous/Follow Up/etc. react to the same captured event.
- Removal of a notification is not proof that a sender deleted a message; store factual lifecycle/reason only.
- Reconcile active notifications on listener reconnect.

FREE / PREMIUM BASELINE
- Free monitored apps: max 3.
- Premium monitored apps: unlimited.
- Free history retention: fixed 7 days.
- Premium retention: 1 / 3 / 7 / 30 days / forever.
- Protected items must be excluded from automatic cleanup.
- Base accessibility/visual alert capability must not be crippled solely to create a paywall.

UX
- Material 3, calm/minimal/comfortable utility aesthetic.
- Device language by default; EN/IT/ES/FR/PT baseline.
- Progressive permission requests: ask only when needed.
- Profile is the administrative center for account, security, language, storage, retention, privacy and permission health.

ENGINEERING
- Native Android Kotlin + Jetpack Compose remains justified because the product depends heavily on Android notification, overlay, sensor and camera APIs.
- Keep dependencies minimal.
- No unrelated AI/network stack unless a future approved feature requires it.
- Database changes require explicit migrations once schema v1 is released.
- Performance, battery use and app size are product features.
