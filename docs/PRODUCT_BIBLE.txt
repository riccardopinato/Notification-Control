NOTIFICATION CONTROL — PRODUCT BIBLE v0.4
Date: 2026-10-02
Status: BASELINE APPROVATA

==================================================
1. IDENTITÀ DEL PRODOTTO
==================================================
Nome: Notification Control
Piattaforma iniziale: Android
Base/donor principale: The Luminous Infinite Circle
Design system: Material 3, soft utility aesthetic, dark mode
Stack: Kotlin + Jetpack Compose

Notification Control è un sistema locale di controllo, conservazione e automazione delle notifiche Android.
Non è una semplice notification history app: cattura una notifica una sola volta, la normalizza, la salva nel Vault locale e la rende disponibile a più moduli senza duplicazione di listener o dati.

Proposta di valore:
- non perdere ciò che è arrivato;
- capire cosa conta;
- ridurre il rumore;
- trasformare notifiche importanti in azioni;
- mantenere il controllo dei dati sul dispositivo;
- offrire avvisi visivi avanzati tramite Luminous.

==================================================
2. PRINCIPI NON NEGOZIABILI
==================================================
1. Local-first: contenuto notifiche e media preview restano sul dispositivo.
2. Nessun cloud obbligatorio per le funzioni core.
3. Single Capture: un solo NotificationListenerService canonico.
4. Single Vault: una sola fonte persistente per storico/undo/message archive.
5. Multiple Consumers: Rules, Critical, Follow Up, Pickup e Luminous consumano lo stesso evento.
6. Privacy by default: nessun contenuto notifiche usato per advertising o analytics.
7. Security by default: protezione locale tramite tecnologie Android appropriate.
8. Premium = automazione, controllo e tranquillità; il Free deve restare realmente utile.
9. Accessibilità Luminous fondamentale non deve essere resa inutilizzabile dal paywall.
10. Performance e consumo batteria sono requisiti di prodotto.
11. Stringhe UI sempre centralizzate e localizzabili.
12. Permessi richiesti progressivamente, solo quando servono.
13. La rimozione di una notifica non prova che il mittente abbia eliminato un messaggio.

==================================================
3. ARCHITETTURA FUNZIONALE
==================================================
ANDROID NOTIFICATION
    -> Notification Capture Core
    -> Normalizer + Deduplication
    -> Local Event Vault
        -> Notification Undo
        -> Message Vault
        -> Critical Alert
        -> Follow Up
        -> Pausa Ping
        -> Pickup Code
        -> Luminous Visual Alerts
        -> Rules Engine
        -> Retention / Cleanup

Il Vault è la source of truth locale.
Notification Undo non crea una seconda copia dei dati: usa la copia canonica già presente nel Vault.

==================================================
4. MODULI V1
==================================================
A. Notification Capture Core
- intercetta le notifiche autorizzate;
- normalizza package, app, titolo, testo, timestamp, mittente e conversation metadata quando disponibili;
- deduplica aggiornamenti multipli;
- separa posted/updated/removed;
- riconcilia le notifiche attive alla riconnessione del listener.

B. Local Event Vault
- storico locale;
- ricerca e filtri;
- elementi protetti;
- cancellazione manuale;
- retention automatica;
- metriche spazio occupato.

C. Message Vault / Notification Undo
- conserva il contenuto che Android espone tramite la notifica;
- può mantenere messaggi non più presenti successivamente nell'app sorgente;
- "Undo" nella v1 significa recuperabilità/storico dal Vault, non ripubblicazione nel notification shade;
- non promette recupero retroattivo o accesso al database interno di WhatsApp/Telegram.

D. Critical Alert
- contatti/app/parole chiave prioritarie;
- escalation Premium;
- bypass opzionale di Pausa Ping e Quiet Hours;
- integrazione Luminous.

E. Follow Up
- trasforma una notifica in promemoria;
- snooze;
- lista Da gestire;
- ripetizioni Premium.

F. Pausa Ping
- cooldown;
- raggruppamento raffiche;
- eccezioni Premium;
- riduzione rumore senza bloccare eventi critici.

G. Pickup Code
- estrazione di codici quando tecnicamente rilevabili dal testo della notifica;
- copia one-tap;
- pin temporaneo;
- scadenza automatica Premium;
- nessuna promessa di cattura OTP sensibili/redatti dal sistema.

H. Luminous Visual Alerts
- donor: The Luminous Infinite Circle;
- flash base;
- overlay/cerchio luminoso OLED-black;
- face-down/proximity;
- Battery Guard;
- Quiet Hours;
- pixel shifting;
- profili avanzati Premium per app/contatto.

I. Rules Engine
- condizioni su app, mittente, parole, tempo, stato;
- azioni multiple sullo stesso evento;
- Free: 2 regole;
- Premium: regole illimitate e concatenate.

7. MEDIA PREVIEW ARCHIVE
==================================================
Notification Control usa come fonte primaria le immagini realmente esposte dalla notifica.
Non promette la foto originale inviata via WhatsApp/Telegram.

Pipeline primaria:
1. ricezione notifica;
2. tentativo immediato da MessagingStyle dataUri con MIME image/*;
3. fallback a BigPicture / EXTRA_PICTURE / EXTRA_PICTURE_ICON;
4. estrazione sicura;
5. ridimensionamento immediato;
6. copia locale compressa max circa 1280 px sul lato maggiore;
7. formato compresso supportato dalla piattaforma;
8. salvataggio locale;
9. cancellazione secondo retention.

Fallback WhatsApp opzionale:
- Premium;
- consenso esplicito dell'utente all'accesso alle foto condivise;
- solo media visibili tramite Android MediaStore, mai database o storage privato WhatsApp;
- correlazione temporale con una notifica WhatsApp appena ricevuta, con finestra controllata prima/dopo l'evento;
- verifica anche OWNER_PACKAGE_NAME quando MediaStore lo espone, oltre al percorso WhatsApp;
- retry progressivi fino a circa 40 secondi per attendere indicizzazione lenta del media;
- il fallback viene rilanciato anche dopo una riconnessione del NotificationListener;
- se più immagini sono compatibili e l'associazione è ambigua, non viene salvata alcuna immagine;
- ogni revisione della notifica può conservare il proprio media: nuove foto nella stessa conversazione non devono sostituire le precedenti;
- retention, cleanup e backup cifrato devono includere tutti i media delle revisioni;
- esclusione delle cartelle Sent;
- nessuna scansione retroattiva della galleria;
- su Android 14+ l'accesso alle sole foto selezionate non è sufficiente per il recupero automatico in background;
- il permesso READ_MEDIA_IMAGES richiede valutazione e dichiarazione Google Play prima della release pubblica.

Il file originale a piena risoluzione non viene conservato di default: anche una foto recuperata dai media condivisi viene copiata nel Vault come versione locale compressa fino a circa 1280 px, sufficiente per una consultazione più affidabile senza trasformare il Vault in una copia completa della galleria.

==================================================
15. DONOR AUDIT DECISIONS
==================================================
Confermato riutilizzabile:
- CameraManager flash engine concept;
- Quiet Hours calculation;
- circle rendering concept;
- pixel shifting concept;
- proximity/pocket sensing;
- Material 3 foundation;
- local diagnostics/test concepts.

Correzioni:
- donor non aveva Vault né parsing contenuto notifiche;
- donor non aveva vera face-down detection basata su accelerometro/gravity;
- proximity non sopprimeva coerentemente flash e overlay;
- “AOD” donor era TYPE_APPLICATION_OVERLAY che accende/mantiene lo schermo, non hardware/system AOD;
- reminder donor era globale;
- Billing donor non era production-safe;
- RECEIVE_SMS / READ_CALL_LOG esclusi dall'architettura target;
- entitlement non deve stare nei renderer Luminous.
