NOTIFICATION CONTROL — AGENT RULES

Source-of-truth order:
1. docs/PRODUCT_BIBLE.txt
2. docs/ROADMAP.txt
3. PROJECT_RULES.txt
4. current implementation
5. current task

Execution rules:
- Inspect only files relevant to the active roadmap step.
- Do not re-audit or re-read GitHub between consecutive steps unless remote state may have changed or the user asks.
- Keep main stable. Use focused branches/PRs for meaningful work.
- One NotificationListenerService only: NotificationCaptureService.
- One canonical local Vault only. Features consume the same captured event; never duplicate capture pipelines.
- Preserve local-first behavior. Core notification content must not require or silently use cloud services.
- Business limits and Premium rules must be centralized, never scattered through UI code.
- Never grant Premium because Billing is unavailable. Debug entitlement simulation must be isolated from release code.
- Do not add QUERY_ALL_PACKAGES, READ_CALL_LOG, RECEIVE_SMS or similarly sensitive permissions without a documented product need and Play-policy review.
- All new user-facing strings must use resources and be prepared for EN/IT/ES/FR/PT.
- Prefer Material 3 components, accessibility semantics, dark mode, and low-friction flows.
- Add/update tests for capture, persistence, retention and business limits when touching those areas.
- Update docs/ROADMAP.txt when a material step changes state.
- Final report must list modified files, tests run, tests not run, risks and next step.
